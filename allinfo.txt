Name        : SignAction
Full Title  : SignAction: Multimodal Assistive Communication System for
              Hearing Impaired Using Speech and Vision
Type        : Full-Stack Web Application + Python Library
Domain      : Assistive Technology / Accessibility / NLP / Computer Vision
Purpose     : Translates typed English text OR live/recorded speech into
              sign-language-like "gloss" tokens and renders them as an
              animated visual gesture sequence (GIF/MP4).

Key Innovation:
  • Eliminates dataset dependency entirely — uses AI-generated skeletal
    animations (ISL-inspired) as fallback for any missing sign assets.
  • Offline-first design: all STT and NLP processing runs locally with
    zero cloud dependency, ensuring privacy and low latency.

  4. FEATURES & CAPABILITIES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  INPUT METHODS
  • Text Input     : Direct typed English text translation
  • Audio File     : Upload .wav / .flac / .ogg files for transcription
  • Microphone     : Live microphone recording (N seconds configurable)
  • WebM Convert   : Auto-converts browser webm audio → wav via ffmpeg

  NLP PROCESSING
  • Lemmatization  : Reduces words to base forms (running → run)
  • Stopword Filter: Configurable removal of non-semantic words
  • Pronoun Map    : I→ME, you→YOU, we→WE, they→THEY, etc.
  • Filler Removal : Drops "um", "uh", "like" automatically
  • Negation Keep  : Preserves "not", "no", "never" in gloss
  • WH-Word Keep   : who/what/where/when/why/how always retained
  • Text Normalize : Regex whitespace cleanup, strip

  SIGN TRANSLATION
  • Lexicon Config : JSON-based aliases and multi-word phrase mapping
  • Asset Resolver : Case-insensitive file lookup across flat/structured dirs
  • Fingerspelling  : Automatic letter-by-letter fallback for unknown words
  • AI GIF Fallback: ISL-inspired skeletal animation for any missing token

  AI ANIMATION ENGINE (ai_fallback.py)
  • 20+ ISL sign definitions (HELLO, HELP, THANK YOU, LOVE, WORK, etc.)
  • Handshape types: flat, fist, point, V-sign, hook, pinch
  • Body landmark anchoring: forehead, chin, chest, neutral space, cheeks
  • 24-frame animated GIFs, deterministic per token (MD5 hash-based)
  • 4 distinct fallback motion families for unrecognized words
  • ISL sign sources: ISLRTC dictionary, IIT-Madras corpus, INCLUDE dataset

  RENDERING
  • Multi-format   : GIF, MP4, static image support
  • Frame caching  : LRU cache with mtime-based cache invalidation
  • Hold frames    : Configurable pause between signs for readability
  • Sequence stitch: All tokens merged into one animated output GIF

  API ENDPOINTS (FastAPI)
  • GET  /health              → Health check + model status
  • POST /translate           → Text → GIF (base64 or file)
  • POST /speech/transcribe   → Audio → Text
  • POST /speech/translate    → Audio → Text → GIF
  • GET  /dictionary          → List available sign tokens
  • GET  /assets/*            → Static sign asset serving

  CLI INTERFACE
  • signaction text  --text "hello world" --out out.gif
  • signaction audio --path sample.wav --backend vosk --out out.gif
  • signaction mic   --seconds 4 --backend vosk --out out.gif

  6. KEY DESIGN DECISIONS & ENGINEERING CHOICES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1. OFFLINE-FIRST STT: Chose Vosk (Kaldi-based) over cloud APIs like
     Google/AWS because it runs entirely locally — zero latency from
     network roundtrips and complete privacy. Also supports Whisper
     as a swappable backend via abstract factory pattern.

  2. AI-GENERATED ANIMATIONS: Instead of requiring a large pre-downloaded
     sign dataset, implemented a Pillow-based skeletal animation renderer
     (ai_fallback.py) that produces ISL-inspired GIFs deterministically
     using NumPy math. This makes the system work out-of-the-box with
     zero assets downloaded.

  3. DATASET-INDEPENDENT DESIGN: All known-word signs are looked up in
     a file-based lexicon. Unknown words automatically fingerspell
     (P-Y-T-H-O-N). If even letter assets are missing, AI animations
     generate them on the fly. The system NEVER hard-fails due to missing
     data.

  4. LRU CACHING WITH MTIME INVALIDATION: The render module caches loaded
     GIF frames keyed by (path, mtime_ns) so re-renders are fast without
     serving stale data after asset updates.

  5. MODULAR STT FACTORY PATTERN: STT backends (Vosk, Whisper) implement
     a shared abstract base, allowing seamless swapping via the factory.

  6. CONFIGURABLE GLOSSING: NLP glossification is parameterized —
     stopword removal, lemmatization, and filler dropping can be toggled
     per-request, enabling fine-grained control.

  7. DECOUPLED DEPLOYMENT: Frontend (Next.js) and backend (FastAPI) are
     fully independent services connected only via the
     NEXT_PUBLIC_API_URL env var — enabling Vercel + Render/Railway
     split deployment.

  8. PACKAGEABLE PYTHON LIBRARY: The core signaction package is pip-
     installable with extras (mic, video, whisper, kaggle, dev) so any
     Python app can import and use it programmatically.

  9. KNOWN LIMITATIONS & FUTURE SCOPE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Current Limitations:
  • NLP gloss rules are heuristic-based, not a full linguistic model
  • AI animations approximate ISL — not certified sign language
  • Vosk accuracy degrades with accents and noisy environments
  • No real-time streaming; processes full utterances at once
  • No emotion/non-manual marker recognition
  • WebM → WAV conversion requires ffmpeg installed on server

  Future Scope / Roadmap:
  • Replace heuristic NLP with a trained seq2seq gloss model
  • Add emotion-aware gesture modulation (voice tone analysis)
  • Integrate 3D avatar rendering for more realistic sign display
  • Real-time streaming speech recognition
  • Mobile app (React Native) wrapper
  • Bidirectional system: sign recognition (camera) → text

  "What problem does this project solve?"
  → Bridges the communication gap for 70M+ hearing-impaired individuals
    by translating everyday English (typed or spoken) into visual sign
    sequences in real-time, without needing internet or large datasets.

  "What was the most technically challenging part?"
  → Designing the AI animation fallback system. I had to encode ISL sign
    descriptions (body location, hand shape, movement) mathematically
    into frame-by-frame coordinates using NumPy trigonometry and render
    them as animated GIFs with Pillow — all without a graphics engine.

  "How did you ensure the system works even without sign assets?"
  → 3-tier fallback: 1) Check real asset files, 2) Generate AI skeletal
    animation for the token, 3) Fingerspell word letter-by-letter. Each
    tier is independently triggered, so the system NEVER fails silently.

  "Why did you choose Vosk over Whisper or Google STT?"
  → Privacy and latency. Vosk runs fully offline using Kaldi acoustic
    models — no audio ever leaves the device. I still architected Whisper
    as a swappable backend via abstract factory pattern for cases where
    higher accuracy is needed with internet available.

  "How is this system scalable?"
  → The frontend and backend are decoupled microservices. The Python core
    is packaged as a pip library reusable in any Python project. The
    asset system scales via Kaggle API integration for bulk dataset
    downloads. Docker containerization enables horizontal scaling.

  "What design patterns did you use?"
  → Factory pattern (STT backends), Strategy pattern (render engine
    per media type), LRU cache with cache invalidation (frame caching),
    Abstract base class (STT interface), Singleton with lru_cache (NLP
    model loading).

  "How does the NLP pipeline work?"
  → Text goes through spaCy tokenization → POS tagging → lemmatization
    (base forms) → pronoun map substitution → stopword/filler removal
    → uppercase gloss token list. This mirrors how professional sign
    language interpreters mentally process English before signing.

  Communication barriers significantly limit interactions between the deaf
  community and the hearing world. This project presents SignAction, a
  multimodal assistive system that dynamically translates typed text and
  spoken speech into sign-language-like "glosses" and renders them as
  visual gesture sequences. The pipeline integrates an offline Speech-to-
  Text engine (Vosk, Kaldi-based) for privacy-preserving transcription, a
  Natural Language Processing module (spaCy) for linguistic normalization
  and gloss generation, and a rendering engine that maps tokens to GIF/MP4
  sign assets. A key contribution is the AI-generated animation fallback
  system — a Pillow/NumPy-based ISL skeletal renderer that deterministically
  produces animated gesture GIFs for any vocabulary token, eliminating the
  dataset dependency that plagues existing solutions. The system provides a
  three-tier fallback strategy (real asset → AI animation → fingerspelling)
  ensuring uninterrupted output for arbitrary input. Delivered through a
  FastAPI backend and Next.js frontend, with Docker containerization and
  cloud deployment support, SignAction demonstrates that accessible, real-
  time sign language communication is achievable with modern open-source
  tooling.

  Gloss Generation, Animation Synthesis, FastAPI, Accessibility
